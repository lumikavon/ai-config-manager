# 产品范围、架构与验收故事

本项目只管理当前用户的 OpenAI 配置；不调用收费模型 API，不上传配置，不提供模型网关。桌面用户与同一系统用户的受信任本地程序是使用者；不能防御已控制该用户会话的恶意程序。

## 信息架构与流程

配置页 → 读取脱敏视图 → 编辑 URL/模型/新密钥 → 校验 → 乐观版本检查 → 保存 → 成功后刷新视图及历史。历史页展示最近十次记录。设置页展示托盘、自启动实际状态、静默启动和语言。

配置文件、锁文件、非敏感恢复日志和历史由核心库统一处理；前端不得读文件或接触已保存密钥。Tauri 命令只承接类型化请求，通过阻塞任务池调用核心。CLI/Skill 与 GUI 复用同一核心，不再实现第二套 YAML/加密逻辑。

## 层次

- React/TypeScript：表单、加载/错误/成功状态、国际化与无障碍交互。
- Tauri 2：IPC、窗口、托盘、自启动、应用设置。
- ai-config-core：校验、YAML 保留、并发控制、持久化与恢复、加密、安全存储、历史。
- ai-config CLI + Skill：脱敏读取、校验和历史查询，明确失败码；受信任 Rust 集成使用内存中配置，不输出凭据。

## 顺序故事与完成条件

1. 基础与边界：独立 workspace、类型化 IPC、默认配置路径；构建验证。
2. 配置持久化：新增/编辑/保留未知字段、原子替换、并发冲突拒绝；临时目录集成测试。
3. 安全密钥：AES-GCM 随机 nonce、系统安全存储、失效密钥失败关闭；模拟 vault 的正反测试，原生安全存储另行验收。
4. 历史：成功提交后记录、最多十条、脱敏 diff、稳定规范化摘要、崩溃恢复；故障注入与持久化测试。
5. 交互：三个页面、空/加载/错误/成功/未解密状态、危险降级确认；组件测试及生产构建。
6. 桌面系统：托盘、真正退出、静默启动恢复、系统实际自启动；编译加各 OS 手工验收，不以模拟代替原生验证。
7. Skill：与核心一致的错误和读取语义，默认无秘密输出；CLI 集成测试。
8. 发布：锁定依赖、完整 README、清洁构建与逐项复核，明确未验证的原生运行门槛。

每个故事异常包括无权限、文件损坏、依赖/安全存储不可用、重复操作和取消。任何不能证明通过的验收记录为未验证，而非成功。
