# Repository guidance

## Development and verification

- Use Rust 1.90.0 (`rust-toolchain.toml`) and Node 22 or 24 LTS; install JS dependencies with `npm ci`.
- Full baseline: `powershell -File scripts/verify.ps1` on Windows, or `sh scripts/verify.sh`. These run `npm ci` → `npm test -- --run` → `npm run build` → `cargo test --locked` → `cargo fmt --all -- --check`. `npm run build` includes TypeScript checking; there is no separate lint/typecheck script.
- Root `cargo test --locked` tests only core and CLI (workspace `default-members`), not the desktop crate. Desktop tests: `cargo test --locked -p ai-config-manager`, with native GUI dependencies installed.
- Preferences have a separate, GUI-free test workspace that compiles production `settings.rs`: `cargo test --locked --manifest-path=src-tauri/settings-tests/Cargo.toml`. Root tests and the local verify scripts skip it, but both CI workflows run it.
- Focused frontend test: `npm test -- src/Config.review.test.tsx`; add `-t "test name"` to filter. Vitest already runs once, uses jsdom, and loads `src/test-setup.ts`.
- Focused core test: `cargo test --locked -p ai-config-core --test store external_edit_conflict`; CLI integration tests: `cargo test --locked -p ai-config-cli --test cli`.
- Core/CLI lint check: `cargo clippy --locked -p ai-config-core -p ai-config-cli --all-targets -- -D warnings`.
- Start the desktop with `npm run tauri -- dev`. `npm run dev` alone serves port 1420 (strict) but shows the desktop-only screen without a Tauri IPC bridge. UI tests mock commands and provide an inert bridge in `src/test-setup.ts`.
- Desktop bundles: `npm run tauri -- build` → `target/release/bundle`; standalone CLI: `cargo build --locked --release -p ai-config-cli` → `target/release/ai-config[.exe]`. Tauri runs the frontend build itself. CI uses `--no-bundle`, so its native build does not verify installers.
- Release: push a `v*` tag to run `.github/workflows/release.yml`; it re-runs verification, then builds Windows/macOS/Linux bundles and publishes a GitHub Release. Do not move or re-push an existing tag; the workflow publishes for the pushed tag.
- Native build prerequisites are in `README.md`; Linux core-only CI also installs `libdbus-1-dev` and `pkg-config`. Mocks or compilation do not verify vault, tray, autostart, or installer behavior; use `docs/native-integration.md` for native acceptance.

## Boundaries and wiring

- `src/App.tsx` owns all three UI pages and IPC calls; bilingual UI copy lives in `src/i18n.ts`, IPC view types in `src/types.ts`.
- `crates/core` owns YAML, validation, encryption/vault access, locking, atomic saves, and history recovery. Both `crates/cli/src/main.rs` and `src-tauri/src/main.rs` delegate to `Store`; keep storage logic shared. The app does not call model APIs.
- Tauri storage commands run through the `blocking` helper (`spawn_blocking`). When adding IPC commands, update the handler registration in `src-tauri/src/main.rs`, command declarations in `src-tauri/build.rs`, and permissions in `src-tauri/capabilities/main.json`. `src-tauri/permissions/autogenerated` and `src-tauri/gen/schemas` are generated build output.

## Storage invariants

- The live AI config is `~/.config/ai.yml` on every OS, including Windows; app preferences use Tauri's app config directory. Tests must use dedicated temporary paths and synthetic keys/mock vaults, not the user's config or native credentials. Even reads can create lock files, and history reads can finalize pending transactions.
- Saved keys never return through IPC or CLI output. A blank editor key sends `api_key: null` to preserve the existing key. Do not serialize `Secret` or `ConfigSnapshot`, or add a plaintext fallback when the vault fails.
- Saves require the loaded raw-byte `revision` (`missing` for a nonexistent file). This differs from history `sha256`, which hashes the complete canonical semantic config including the decrypted key. Preserve unknown YAML values, not comments/layout.
- `HISTORY_PENDING` and `COMMIT_UNCERTAIN` can mean the config was already replaced. Reload config and recover/read history before another save; do not blindly retry or delete `.pending.json`. See `docs/core-design.md` for transaction and digest details.
- Autostart reflects queried OS registration, not a saved preference boolean. Tray failure must leave a visible window even with silent startup or close-to-tray enabled.
